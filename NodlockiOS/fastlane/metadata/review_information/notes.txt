Nodlock is a companion app for a free open-source macOS menu-bar utility (github.com/Chocksy/nodlock). When the user's Mac shows a security prompt (e.g. the 1Password unlock dialog), the Mac app sends a push; the user sees a screenshot of the prompt, authenticates with Face ID, types the password, and it is typed into the Mac's dialog over an encrypted channel. It also routes CLI login URLs (OAuth device-code flows) to the phone. Target audience: developers and technical users running automation on a Mac they are not sitting at.

HOW TO REVIEW WITHOUT A MAC: tap "Try a demo" on the pairing screen. It simulates a paired Mac end to end:
1. Launch the app. On the pairing screen tap "Try a demo" (below the paste field).
2. Allow notifications if prompted. An amber banner confirms demo mode; nothing reaches a real Mac.
3. Within ~5 seconds a simulated 1Password unlock prompt appears with a screenshot.
4. Face ID (or passcode) gates the screen; in the demo a failed/cancelled prompt never blocks.
5. Type any text in the password field and tap Unlock. The prompt clears after a moment, simulating a successful unlock. It re-arms a few seconds later so the flow can be repeated.
6. Scroll down: "Recent logins" lists a sample CLI login; tapping a row opens the URL.
7. Unpair via the top-right menu ("Unpair the demo Mac") to return to pairing.

NO ACCOUNT, NO LOGIN, NO PAYMENTS: there is no registration, no credentials, no purchases, no subscriptions, no user-generated content.

DATA: the developer operates no server and collects nothing. Passwords transit only from the phone to the user's own Mac over an encrypted channel and are never stored or logged. Push payloads contain only a title, the Mac's hostname, and (for login pings) a URL.

EXTERNAL SERVICES: Apple Push Notification service, and the user's own Mac (local network, or a secure remote connection the user sets up themselves). No data providers, auth services, payment processors, AI services, analytics, or third-party SDKs.

TESTED ON: physical iPhone 15 Pro (latest iOS, Xcode + this TestFlight build); iPhone 17 Pro Max / 11 Pro Max simulators (iOS 26.5). Companion tested on a Mac mini, latest macOS.

REGIONAL DIFFERENCES: none; identical in all regions. REGULATED INDUSTRY: not applicable. "1Password" is referenced descriptively as an example of a macOS prompt; the app does not integrate with or embed 1Password.

PERMISSIONS USED: notifications (prompt alerts), camera (QR pairing scan), Face ID (gate before typing a password). The demo requires none of these to complete.

MAC ACTIONS: an optional card of buttons that appears only when the user's own Mac companion publishes named actions in its status response. Tapping one sends the action id to the user's Mac over the same HTTPS channel. The demo exposes none, so the card is not visible in demo mode.

STATUS TAB (new in 1.2): a read-only overview of the user's own apps and servers, which their Mac companion collects and serves. In the demo it shows sample apps (Shop, Blog, Infra), two sample servers and one sample warning, so tap the "Status" tab at the bottom after step 3 to see it.
